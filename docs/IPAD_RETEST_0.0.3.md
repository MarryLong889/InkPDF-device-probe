# 0.0.2 实机分析与 0.0.3 复测

2026-10-26。修复版 0.0.3，尚未通过 iPad 实机验收。

## 证据与结论

依据用户两份诊断（时间戳 1792978852938、1792978865232）及截图；不将原始诊断或截图纳入公开仓库。

- 同一 run/source，重启前后均 106 笔、revision 103；重读 PASS、无错误，保存和正常重启继续通过。
- PDF 渲染 85 / 112 ms；Worker 9 / 36 ms，基础能力继续 PASS。
- 最近 30 笔全部 pointerup 结束，canceled/lostCapture/captureFailed 均 0，截图可见连续长线。没有记录程序截断的证据，但缺少用户对断笔次数的明确反馈，不能宣称完全解决。采样最大间隔 71 ms，不等于已确认可见断笔。
- 压力范围 0～0.324019，9776 个笔采样，增益 2.5×；压力采集正常，轻重压视觉验收仍待用户反馈。
- 44 次 touchDown 中 42 次 ignoredTouches，touchPanMoves=0，与用户报告滚动失败一致。旧日志无法区分笔接触、多指、180 ms 保护或大于 40px 接触面的拦截；不能确定 42 次都由尺寸规则引起。截图时处于浏览模式，也不能还原之前书写模式尝试的时序。
- 最长增量绘制 2 ms，36 次保存中最长约 1132 ms。该保存耗时是异步流程总耗时，不能直接认定为主线程卡顿。累计快照及完整链校验仍有随历史增长的成本。
- 只恢复一步是 0.0.2 的实现限制，本轮按用户要求扩展为多步擦除恢复。

## 0.0.3 修改

1. 移除没有 iPad 校准证据的 40px 触摸尺寸门槛。仍只允许单指，笔或橡皮接触时禁止启动导航；手指永远不生成笔迹。笔抬起时已经落下的手掌不自动转成导航。
2. 手指在抬笔后 180 ms 内落下时保留候选状态，保护时间内仅更新基准位置；时间过后继续拖动即可，不再丢弃整个触摸序列。
3. 新增 touchDiagnostics：笔接触/多指拦截、保护期移动、最大接触尺寸、收到的移动、实际 scrollTop/Left 变化次数、当前模式、活动触摸数、垂直滚动范围。继续不导出笔迹坐标。
4. 擦除历史保留最多 20 次有效操作，且保留点数不超过 100000；超过预算淘汰最早操作。按钮显示剩余可恢复步数。新书写不会清空历史，恢复只插回被擦除笔迹，保留期间新增的笔迹及顺序。恢复超出探针点数或笔数限制时提示错误并保留历史。
5. 历史只保留在本次视图会话内，重启或关闭视图后不可继续撤销；已经恢复并保存的笔迹会保留。未加入完整撤销/重做、OCR、多页或导出功能。

去掉接触尺寸规则后，抬笔后的单个手掌移动也可能触发导航；需要实机检查这一取舍，不能把桌面合成事件测试当成掌拒验收。

## 复测

发布更新后先确认诊断版本为 0.0.3，保持 Scribble 关闭，确认旧 106 笔仍在。建议新建独立测试，避免接近 200 笔上限。

1. 选择“模式：书写”。在页面中部，抬笔后单指上下拖动。分别立即触摸、等半秒触摸；均应能继续拖动，笔数不变。不要只在页面最底部尝试继续向下滚动。
2. 在笔正在书写时落掌，确认不带动页面、不误画；抬笔后移开手掌，再用单指拖动。200% 下再测试横向拖动。
3. 画 A、B、C 三条分开的线。分三次擦除，再连续点三次“恢复擦除”；预期按 C、B、A 恢复，按钮步数递减。另测擦除后画新线，再恢复，确认新线未丢失。
4. 点击保存重读，等待“已保存并读回校验”，导出诊断；重启 App 后检查笔数、位置和擦除/恢复结果，再导出一次。重启后恢复历史为 0 是当前预期。
5. 画 20 条连续长线，反馈断笔条数和轻重压是否可见。截图可保留模式按钮、压力读数与笔迹。

若滚动仍失败，请在失败后、重启前立即导出诊断，并说明当时模式、拖动方向、是否已到页面边缘、笔和手掌是否已离屏。新的分项计数可以区分“被拦截”“未收到移动”“没有可滚动距离”。

## 本地验证

构建与 TypeScript 检查通过；15 项核心测试、11 组 Chromium 集成检查通过。包括 64px 接触面拖动、保护时间内开始的同一手指继续拖动、笔接触阻止导航、两次擦除依次恢复、恢复保留新增笔迹、历史预算、超限不丢历史、保存失败重试及擦除后重开。

宿主为模拟 Obsidian，非 iPad WKWebView。发布资产仍仅 main.js、manifest.json、styles.css。发布后可通过 BRAT 更新到 0.0.3。
