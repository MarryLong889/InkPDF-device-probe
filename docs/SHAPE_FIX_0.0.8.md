# 0.0.8：停笔拟合修复与诊断

2026-10-27。0.0.8 发布说明；构建与自动化检查通过，iPad 验收待完成。

## 0.0.7 实机证据

用户反馈连续滚动、工具栏正常，保持接触超过 1 秒仍不拟合。两份诊断是同一个 PDF 的第 2 页，均为 20 笔、revision 32；相邻页也一致：第 1 页 29 笔/revision 15，第 3 页 4 笔/revision 4。第二份记录从磁盘载入相同笔数和版本，无保存错误；诊断不包含坐标，不能据此证明逐点内容完全一致。

首份记录：38 次 Pencil 落笔，取消、丢失捕获、捕获失败均为 0，最后 7 笔持续约 1.9–4.6 秒，但 shapeCounts 为空。PDF 和基础 Worker 检测通过。整笔持续时间不能替代末端稳定停留时间；0.0.7 没有记录计时器触发次数、图形拒绝或工具类型，无法唯一确定本次设备失败原因。

## 已复现的代码缺陷与修复

旧版计时容许 4 CSS 像素以内移动，但拟合仍使用全部采样。细小停笔抖动会不断累加路径长度，使直线的“路径长度/首尾距离”、圆和方框的周长判据失败。浏览器回归在原始 0.0.7 上加入 400 个约 ±0.4/±0.3 CSS 像素的停笔点，复现直线拟合失败（预期 line，实际 undefined）。这证明代码存在此缺陷，不等于已取得用户设备的原始抖动轨迹。

0.0.8 改为在每次有效移动、重新开始计时时记录几何采样边界；停留期间的抖动不参与此次拟合，原始笔迹仍完整保留供撤销。未放宽图形判定、4 像素移动容差或 1 秒门槛。

额外加固：抬笔时用单调时钟补检已满足的停留时间，处理计时器未及时回调的情形。测试用主动延迟计时器验证此路径；尚无证据表明用户的 WKWebView 确实延迟了计时器。提前抬笔、明显移动、取消输入仍不会强制拟合。

状态行现在显示等待、拟合预览成功、几何未识别或点数上限。新增 shapeDiagnostics：eligibleStrokes、skippedHighlighter、armed、movementResets、timerFired、attempts、rejected、pointLimit、previews、canceledPreviews、pointerUpFallbacks、maxHoldMs、ignoredDwellSamples、lastOutcome、工具类型及阈值。仅导出计数和状态，无手写坐标、PDF 字节或内容。

## 验证与范围

构建、TypeScript 检查通过；19 项核心/几何测试、22 组 Chromium 集成检查通过。新增抖动下三种图形拟合、计时器延迟后的抬笔补检、拒绝提示和诊断隐私检查。原有提前抬笔、移动取消、撤销回到原手绘、重做、保存重开、连续翻页与离屏保存失败回归保持通过。

证据：`tests/evidence/browser-0.0.8.json`。本次没有改动滚动、工具栏布局、存储格式、原 PDF 或识别几何算法，也不新增依赖。仍只支持 Pencil 钢笔拟合；荧光笔不拟合，方框只支持与页面边缘平行的方向。

## iPad 针对性复测（发布后）

1. 保存并备份 InkPDF-Probe，BRAT 更新到 0.0.8 后重新启用插件。保持 Scribble 关闭，选择钢笔；可用蓝色，便于看清拟合前后变化。
2. 画长约 3–5 厘米的直线，保持笔尖接触约 1.5 秒再抬笔。观察状态行是否依次显示等待和“已拟合直线”。重复 5 次；再各画 5 个闭合正放方框和圆。
3. 若没有变形，记录状态行：始终等待、已检测但未识别、曾出现拟合后又恢复，或仅抬笔后拟合。短录屏需同时包括笔迹和状态行。
4. 验证少于 1 秒抬笔不拟合；预览后明显移动应恢复手绘。拟合确认后撤销一次恢复原手绘，重做恢复拟合，再保存读回、重启检查结果。
5. **测试结束后、重启之前先导出一份诊断**，确保触发计数未被重置；重启后再导出同页诊断核对保存。回传两份 JSON 和上述现象/短录屏即可，不需要发送私人 PDF。

若仍失败，新增字段可区分未使用钢笔、移动反复重置计时、满足时间后几何拒绝、预览取消和计时器延迟，再根据实机证据调整；不能将本地模拟通过宣称为 iPad 已修复。
